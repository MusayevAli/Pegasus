# TripFit integration contract

All prices are illustrative EUR integer cents. All inventory is demo, even with live AI enabled.

Backend default: http://127.0.0.1:3001; dashboard Vite 5173 proxies /api to backend.

POST /api/events { events: Event[] } -> { accepted: number, duplicates: number }. Event: id string UUID, name string, sessionId string UUID, flowId string UUID, screen string, componentId string, sequence integer, clientTimestamp ISO string, appVersion "1.0", schemaVersion 1, provenance "demo" | "live" | "synthetic", properties object with allowlisted typed fields. serverReceivedAt generated by server.

Names: search_submitted, results_shown, no_results, screen_viewed, screen_duration, step_completed, preference_changed, filter_changed, offer_compared, offer_selected, connection_opened, baggage_changed, seat_changed, meal_changed, validation_error, back_navigation, checkout_started, checkout_cancelled, checkout_failed, demo_booking_completed, ticket_issued, recommendation_generated, recommendation_visible, recommendation_expanded, recommendation_accepted, recommendation_dismissed, recommendation_applied, recommendation_reversed, recommendation_retained.

Screens: search, itinerary, configuration, baggage, seats, meals, review, checkout, confirmation, trips. Funnel folds baggage/seats/meals into configuration; direct optional skips do not create dropout.

Properties allowlist: journeyId, origin, destination, partySize, resultCount, code, direction, productId, segmentId, passengerType, valueMinor, totalMinor, extrasMinor, foregroundMs, activeMs, visitId, recommendationId, recommendationType, choice, previousScreen, completed, revision. Never notes, names, images, payment tokens, arbitrary text.

GET /api/analytics?provenance=synthetic|demo|live|all&days=7|30|90 -> dashboard metrics. Exact response types are defined in `shared/analytics.ts`. GET /api/sessions/:id for consented timeline. GET /api/health.

Legacy compatibility route: POST /api/ai/guidance {revision:integer, note:string, journeyId:string, passengerTypes:string[], segmentIds:string[], preferences:string[]} -> {revision, source:"demo"|"openai", cards:[{id,type,passengerIds:[],segmentIds:[],productIds:[],explanation,clarificationChoices:[],requiresConfirmation:true}]}. No identity. Types: baggage, meals, seating, bundle, connection, keep_allowance. Catalogue products: peg-cabin, peg-checked20, peg-checked25, peg-meal-child, peg-meal-veggie, peg-meal-classic. Bundles: basic, family, flex. Seats use separate seat IDs (rows 1–8, columns A–F), not generic product IDs. Guidance preferences: light, gifts, business, sports, together, budget, vegetarian, no_alcohol, child_meal. Client rejects stale revision.

GET /api/ai/status (app-token protected) -> {configured:boolean,model:string,features:["trip_plan","packing_vision","aggregate_insights"]}. Configured means a provider client exists, not that the account/model request has succeeded.

POST /api/ai/plan uses the same validated input as guidance: {revision:integer,note:string,journeyId:string,passengerTypes:string[],segmentIds:string[],preferences:string[]}. Exact response:

```ts
{
  revision: number;
  source: "openai" | "local";
  model: string | null;
  summary: string;
  needs: {
    travellingLight: boolean | null;
    giftsOnReturn: boolean | null;
    stayTogether: boolean | null;
    noAlcohol: boolean | null;
    vegetarian: boolean | null;
    checkedBagEachWay: boolean | null;
    mealsEachFlight: boolean | null;
    packingItems: Array<"clothes" | "laptop" | "gifts" | "sports" | "liquids">;
  };
  clarifications: Array<{
    id: "packing" | "meals" | "seating";
    question: string;
    choices: Array<"travel_light" | "checked_bag" | "vegetarian" | "meals" | "no_meal" | "together" | "skip">;
  }>;
  notice: string;
}
```

Plan summaries retain the successful model's personalised text. Nullable flags express new note intent only: null preserves existing client choices, false explicitly declines a need. Existing chips are context and do not fill unstated flags. checkedBagEachWay/mealsEachFlight true applies to every traveller on every supported flight; unclear scope asks for clarification. A vegetarian preference alone does not add meals. No result applies purchases or supplies prices. The client calculates catalogue-priced options and requires user confirmation. Missing/invalid AI uses source local, model null and an explicit limited-phrase-matcher notice. Clients reject stale revisions. Note limit: 600 characters; summary: 400; at most 3 questions (160 characters each) and 5 packing categories; all output objects are strict.

POST /api/ai/packing {revision,imageBase64:string|null,mimeType:"image/jpeg"|"image/png"|"image/webp"} -> {revision,source:"openai"|"local",model:string|null,summary:string,candidates:Category[],items:[{category:Category,label:string,confidence:"low"|"medium"|"high"}],questions:string[],requiresConfirmation:true,notice:string}. Category is clothes|laptop|gifts|sports|liquids. candidates derives from validated items. Summary limit: 320 characters; label: 80; at most 5 unique categories and 3 questions of 160 characters. User confirms/corrects all items; no photo measures weight or dimensions. No key/photo or any invalid/unavailable model response returns source local, model null, empty candidates/items/questions and a notice that the photo was not analysed. No sample detections are substituted.

POST /api/quotes validates selections and creates expiring server-side quote; POST /api/payments uses idempotency key and server quote; no simulated response may claim issued.

Journey IDs: family (SAW–BCN), us-connection (JFK–SAW via same-airport external connection), solo (SAW–AYT). Passenger IDs: adult-1, adult-2, child-1, and similarly numbered travellers. Segments: family-out, family-in, us-external, us-pegasus, solo-out. Family offers support one-way and round-trip; the other prototype offers are one-way only.

POST /api/quotes body: {journeyID, adults, children, roundTrip, revision?, selection:{bundle,extras:[{passengerID,segmentID,productID}],seats:[{passengerID,segmentID,seatID}],meals:[{passengerID,segmentID,productID}]}}. Note quote/domain keys use uppercase ID, whereas event and AI transport keys use lower camel Id. Quote response: {id,currency:"EUR",baseMinor,extrasMinor,totalMinor,items:[{label,amountMinor}],expiresAt,revision,inventorySource:"demo"}.

POST /api/payments body: {quoteID,idempotencyKey,mode:"demo"|"apple_pay",paymentToken?}. Demo success returns state:"completed_demo", authorization:"simulated", capture:"not_charged", issuance:"not_issued", and a DEMO reference. Demo inventory is never charged; apple_pay currently returns live_provider_unavailable.

Screen-duration properties are incremental checkpoint deltas with a stable visitId. Checkpoint before emitting booking completion. Actual recommendation retention requires recommendation_retained, emitted only after the client verifies the selection remains applied. Synthetic events and ticket_issued cannot be posted by untrusted clients; live session timelines are suppressed.

Native pure Swift core: ios/Sources/TripFitCore and ios/Tests. App and Xcode project: ios/App and ios/PegasusTripFit.xcodeproj. Package.swift exposes TripFitCore for Foundation-only tests. Full iOS simulator compilation was verified using Xcode 26.3 at /Applications/Xcode.app; simulator interaction/accessibility checks are separately recorded.
